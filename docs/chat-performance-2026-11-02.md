# 多轮问答的前端性能排查

本轮处理输入、滚动和窗口切换变卡，与模型服务首字延迟分开。

## 参考项目

- [Streamdown memoization](https://streamdown.ai/docs/memoization)：缓存不变化的 Markdown 和已完成内容，避免每个流式片段都重算历史。当前实现采用消息历史与 Markdown 组件缓存，未替换现有公式渲染器。
- [assistant-ui virtualization](https://www.assistant-ui.com/docs/guides/virtualization)：消息更新隔离，超长对话按可见行挂载。其默认方案也使用浏览器屏幕外渲染优化。本轮先移除实测的重复工作；未引入完整虚拟列表。
- [React Activity](https://react.dev/reference/react/Activity)：隐藏 UI 时清理 Effect，恢复时保留状态和 DOM。只用于追问历史，发请求的父组件保持运行，以满足关闭窗口后继续回答的约定。

## 已定位并修复

1. 输入框、等待计时和流式文本都在追问面板中更新；历史消息直接在同一组件 map，导致历史 Markdown、公式与选区 Effect 一并重复执行。隔离并 memo 历史组件，memo 共享 Markdown 组件。
2. 没有任何标记的回答也创建 ResizeObserver、MutationObserver 和布局监听。现在只有存在有效高光范围的内容安装这些观察器；相同矩形不更新 React 状态。
3. 关闭的窗口仅设置 hidden，历史内容的全局选区监听继续工作。Activity 隐藏历史后暂停其 Effect，草稿、阅读位置和后台请求保留。
4. 每个 NDJSON 片段直接触发更新。首段仍立即显示，后续片段按 50 ms 合并；完成、出错和中断时提交最后一批临时文字，不把不完整回答标记为保存成功。

## 本地对比

脚本：`tests/browser/chat-performance.mjs`。所有业务 API 使用固定假数据，不向真实模型发送请求、不修改文档。Windows / Edge headless / Next 开发服务，同一份 12 轮对话、96 个公式，输入同样的 31 个英文字符。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 自动连续输入耗时 | 6822 ms | 158 ms |
| 输入期间选区监听重复绑定 | 372 | 0 |
| 打开时高光布局观察目标 | 13 | 1 |
| 关闭后的全局选区监听 | 14 | 2 |

时间是本机一次自动化运行的结果，包含浏览器测试驱动开销，不是生产环境延迟承诺。监听数量与行为断言比耗时更适合作为回归门槛。原始指标输出在 `.build-cache/chat-performance/`，自动化不对时间设不稳定阈值。

## 后续边界

当前仍保留全部历史 DOM，特别长的单个回答仍会对当前流式内容重新解析。数百轮以上可以进一步评估按段缓存和虚拟列表，但需要同时适配高光文本偏移、跨消息选择、随心笔记定位及用户主动控制的滚动，避免优化造成原文定位错误。本轮没有改变持久数据或文本偏移格式。
